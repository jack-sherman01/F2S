03

The central finding: a missing applicability check, found and fixed

retrieve() matched skills by failure-mode id alone; with only one implicit mode, the match score cleared threshold on every stall regardless of whether the current state resembled anything the skill was validated on. A skill tuned to one exact object position got replayed into unrelated states, repeatedly.

Fix: f2s/skills/retrieve.py's spatial_gate_passed — a skill is only retrieved if the current object position is within the same 3cm neighborhood Day-19 validation itself tested. This is the Match(S,F_k,s_t) state-aware retrieval the revised proposal calls for.

Ablation: sophistication backfires

Required comparison per the revised proposal. "F2S w/o World Model" already lacks both minimum-required ablations (no failure clustering, no world-model ranking) — it's the method that found every real skill in this project.

Full F2S executed 1,278 real candidates across the same 6-offset sweep and found zero archivable skills — its 72.2% is mathematically Fixed Policy's number, since an empty archive means retrieve() never returns a match. Clustering has no effect on CEM's own candidate generation in this codebase (cem_search has no historical-reuse parameter) — it only labels results.

Three real evolution rounds: a flat line, honestly reported

Production defaults (configs/f2s_final.yaml, unmodified), fixed pipeline, 50 episodes/round. 13.4 minutes wall time.

Archive size is zero at every round — CEM-based discovery (66 real executions total across 3 rounds) never finds an archivable skill, reproducing the ablation finding from inside the real loop. The 74.0% → 72.0% → 68.0% drift is 50-episode sampling noise: with an empty archive, every round is a plain frozen-policy rollout under a new random draw, not learning or degradation.
